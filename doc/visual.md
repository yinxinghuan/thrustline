# THRUSTLINE 灰盒视觉与界面合同

## 1. Thesis

这不是美术方向，而是诊断仪表：玩家必须一眼看见飞行器、山脊、两个平台、推力状态、速度和预测落点。

## 2. Composition / Camera

固定竖屏正交视图，`360×640` 逻辑场地填充可用空间。HUD 占顶部 `70px`，玩法仍可穿过其下方；山脊位于下部，两个平台同时可见。READY 火箭位于逻辑坐标 `(160,160)`，首帧 `-6°`，火箭权威几何顶部距场地顶边 `145px`，与左右边分别保留 `145px / 185px`。教程卡位于场地高度 `44%`，宽不超过 `248px`、高约 `78px`，必须与火箭及两个平台分离。平台内构图不为外部访客栏让位。

气流权威边界仍为 `x=162–232`；标签绘制在边界右上方，不与 READY 火箭叠压，标签位置不改变物理范围。

## 3. Color

- 背景 `#f4f2ec`
- 权威山脊/飞行器 `#171717`
- 辅助网格/历史轨迹 `#a9a79f`
- 点火、危险和预测碰撞 `#d4572a`
- 所有状态同时使用文字或形状，不只依赖颜色。

## 4. Typography

系统无衬线，数值等宽；标题 `16px/700`，关键数值 `18–24px/700`，说明文字最小 `14px`。中文或英文按当前语言单独显示，不并排展示翻译；不使用装饰字体。

## 5. Shape / Material / Light

全部为单色线框和实心几何；不模拟材质、灯光、深度、玻璃或金属。飞行器从抽象三角符号提升为克制的具象版画火箭：黑色锥形鼻与短舱体、两枚不完全对称的稳定翼、明确喷口、一个米白菱形舷窗和一条斜刻线。轮廓使用硬边与略不规整切口；禁止渐变、软阴影、光泽、贴纸描边或高科技写实细节。

## 6. Assets

无外部资产、图片、字体、音频或第三方代码。所有地形与 UI 由 Canvas/DOM 原生绘制。

## 7. UI / Icons

不使用功能 Emoji。HUD 用直接文字；重开按钮在中文显示“立即重开”，英文显示 “RETRY”。唯一玩法控件是整个 Canvas。声音按钮使用自绘硬边 SVG 扬声器，`44×44px` 以上，中文显示“开/关”、英文显示 “ON/OFF”，不依赖图标单独传达状态。

## 8. Motion / VFX

反馈层只响应权威状态：点火绘制短硬边压力刻线与最多 `36` 个定向喷屑；近地真实点火才出现贴地扬尘；进入气流时既有流向线发生硬折变形；预测跨入 SAFE/HARD/CRASH 时在真实预测落点显示短促方形刻度；HARD 使用短冲击线，CRASH 使用硬边断裂块，SAFE 使用夹具闭合线。火焰只在 `engine.thrusting && fuel>0` 时出现，熄火不保留残焰。禁止渐变、模糊、软光、透明烟、装饰烟花和持续闪屏。

反馈对象只读引擎状态，不写回 `engine.js`，不参与 hitbox、质心、预测或碰撞。`prefers-reduced-motion` 将喷屑降为每次 `1` 条、风/结果反馈缩短到 `90ms`，并关闭教程与结果位移动画；文字、火焰和权威轨迹保持可读。

## 9. Translated References

保留 Lunar Lander 的重力、燃料、速度阈值和平台风险；将旋转控制转译为自动摆角，让移动端只需按住/松开，同时保留点火时机决策。

## 10. Anti-patterns

- 不用视觉主题掩盖无趣的物理。
- 不显示键盘或虚拟方向键。
- 不把预测线做成虚假装饰。
- 不隐藏速度阈值或失败原因。
- 不用随机噪声制造不可复验的地形。
- 不接排行榜、身份、海报、UUID 或发布壳层。

## 11. Vertical-slice Acceptance

- ready、playing-thrust、playing-coast、SAFE/HARD/CRASH 结果均可读。
- 两个平台与气流区在 `390×844`、`320×568` 同时可见。
- READY 首帧火箭不与教程卡相交，左右视觉边距分别不少于画布显示宽度的 `35% / 45%`；教程卡不遮挡任何平台。
- 首触同帧显示 THRUST，松开后同帧显示 COAST。
- 预测落点与权威碰撞使用同一地形函数，截点误差不超过 `2px`。
- 关闭或减少反馈喷屑后，玩家仍能依靠权威轨迹、速度、燃料和平台完成全部决策。
- READY、THRUST、COAST 及 SAFE/HARD/CRASH 结算徽记必须保持同一锥鼻、舷窗、双翼和喷口识别；320×568 下舷窗仍可辨认，非点火状态不得出现警戒红火焰。
- `zh / en` 的 READY、教程、飞行、暂停和三类结算均不得出现另一语言的并排翻译；两种语言在双尺寸下无横向溢出。

## 12. CRT 机房终端（当前方案）

- 正式方向使用 `ui-style-library` 的 BSOD Pixel / CRT 路径；光学边界参考 Signal Bloom 已验证的 CSS 像素定标、曲率、束偏、扫描调制与边缘孔径合同，但不把项目私有 shader 冒充独立 Skill。
- 整个游戏在厚重石墨机体与内凹显像管内：标题、HUD、权威 Canvas、暂停和结算共享同一玻璃平面。外壳在窄屏压到 7px/侧，所有触控仍位于有效玻璃区。
- 结算通过 `PROGRAM CH-01 → RELAY CUT / VIDEO SYNC → RIDGE CAMERA / VIDEO LOCK` 切换到本地预置媒体；SAFE/HARD/CRASH 分别选择 `thrustline-safe/hard/crash.jpg`，动态 `vx/vy/angle/fuel/pad` 作为 CRT 遥测叠层。
- 取消纸张、印章、热敏纹理与打印动画。媒体本体不烘焙扫描线；统一 CRT 光学层负责磷光栅格、暗角与一次垂直同步。reduced-motion 直接锁定静态媒体。
- 资产镜头与生成来源见 `doc/assets.md`。当前正式媒体是三张高质量静态图；视频未达到可信局部运动门槛，因此不交付伪视频。
- 390×844 使用 `600×430` 证据画布并居中利用高屏；320×568 使用 `600×360` 紧凑画布，重开和声音仍 ≥44px。照片始终是结果页最大元素。
- 回传编排为 `SIGNAL LOCK → 7级硬切显影 → 静止证据`，总计 520ms；reduced-motion 直接显示。禁止渐变、模糊、随机噪点或固定景观换印章。
